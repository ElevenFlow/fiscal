# Phase 02.1 Plan 01: Auth In-House Foundation — Schema + Migration + Shared Zod Schemas Summary

**One-liner:** Migration Prisma que adiciona `sessions` table (refreshTokenHash CHAR(64), RLS permissiva) + campos `password_hash/email_verified_at/password_changed_at` ao model User + remove `clerk_user_id` + schemas Zod `SignupSchema`/`SigninSchema` em `@nexo/shared/auth`.

## What Was Built

### Task 1: Schema Prisma atualizado (commit `03ad249`)

**apps/api/prisma/schema.prisma** — model User modificado e model Session adicionado:

- **User**: removido `clerkUserId` (campo `clerk_user_id`); adicionados `passwordHash VARCHAR(128)`, `emailVerifiedAt TIMESTAMPTZ`, `passwordChangedAt TIMESTAMPTZ` (todos nullable); relação `sessions Session[]`.
- **Session**: novo model com `id UUID PK`, `userId UUID FK → users(id) ON DELETE CASCADE`, `refreshTokenHash CHAR(64) UNIQUE` (sha256 hex), `ip VARCHAR(45)`, `userAgent VARCHAR(500)`, `expiresAt`, `createdAt`, `revokedAt`; índices em `[userId, expiresAt]` e `[refreshTokenHash]`.

Schema validado: `prisma validate` exit 0.

### Task 2: Migration + Zod schemas + redact-paths (commit `10d8f05`)

**Migration 20260427015131_auth_in_house_sessions_password:**
- `ALTER TABLE "users" DROP COLUMN "clerk_user_id"` (+ drop index `users_clerk_user_id_key`)
- `ALTER TABLE "users" ADD COLUMN "password_hash" VARCHAR(128), "email_verified_at" TIMESTAMP(3), "password_changed_at" TIMESTAMP(3)`
- `CREATE TABLE "sessions" (...)` com todos os campos, FK cascade, índices
- `CREATE UNIQUE INDEX "sessions_refresh_token_hash_key"` — garante unicidade do token

**Migration 20260427015200_sessions_rls_permissive:**
- `ALTER TABLE "sessions" ENABLE ROW LEVEL SECURITY`
- `GRANT SELECT, INSERT, UPDATE, DELETE ON "sessions" TO app_user`
- `CREATE POLICY "sessions_permissive_dev" ... USING (true) WITH CHECK (true)` — TODO hardening Plan 02.1-03

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Typecheck falha em clerk.guard.ts após remoção de clerkUserId**
- **Found during:** Task 2 — `pnpm --filter @nexo/api typecheck` retornou error TS2353 em linha 111
- **Issue:** `clerk.guard.ts` usava `where: { clerkUserId: claims.userId }` para lookup de user, e `AuthContext` continha o campo `clerkUserId: string`. Com a remoção do campo do model Prisma, o TypeScript rejeitou.
- **Fix:** Removido `clerkUserId` de `AuthContext`; substituído lookup por stub temporário (`findFirst`) com comentário explícito que `clerk.guard.ts` será deletado em Plan 02.1-02; removido `clerkUserId` de ambos os `req.auth = {...}` (Clerk path e header-auth path).
- **Files modified:** `apps/api/src/modules/auth/clerk.guard.ts`
- **Commit:** `10d8f05`

**2. [Rule 1 - Bug] Typecheck falha em lgpd.service.ts após remoção de clerkUserId**
- **Found during:** Task 2 — error TS2339 em linha 113 (`Property 'clerkUserId' does not exist on type User`)
- **Issue:** `LgpdService.exportTitularData` retornava `clerkUserId: user.clerkUserId` e a interface `ExportPayload.user` declarava o campo.
- **Fix:** Removido campo da interface `ExportPayload.user` e do objeto de retorno, com comentário de remoção.
- **Files modified:** `apps/api/src/modules/lgpd/lgpd.service.ts`
- **Commit:** `10d8f05`

**3. [Rule 2 - Missing] RLS sessions ausente na migration principal**
- **Found during:** Task 2 — o Prisma não gera `ENABLE ROW LEVEL SECURITY` automaticamente; a critical rule do plano exigia RLS na tabela sessions.
- **Fix:** Criada migration adicional `20260427015200_sessions_rls_permissive` com `ENABLE ROW LEVEL SECURITY`, `GRANT` ao `app_user` e policy permissiva com TODO de hardening em Plan 02.1-03.
- **Files created:** `apps/api/prisma/migrations/20260427015200_sessions_rls_permissive/migration.sql`
- **Commit:** `10d8f05`

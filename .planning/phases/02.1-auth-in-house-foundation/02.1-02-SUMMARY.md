# Phase 02.1 Plan 02: Auth In-House — API Auth Module Summary

**One-liner:** NestJS auth module completo substituindo Clerk: PasswordService (argon2id m=65536/t=3/p=4) + JwtService (HS256 via jose) + SessionsService (refresh rotation single-use) + AuthController (signup/signin/signout/refresh/me) + AuthGuard (cookie nf_access) + 38 testes passando.

## What Was Built

### Task 1: PasswordService + JwtService + SessionsService (commit `56ddf50`)

**apps/api/src/modules/auth/password.service.ts:**
- `hash(plain)`: argon2id com `memoryCost:65536, timeCost:3, parallelism:4, outputLen:32`
- `verify(hash, plain)`: constant-time comparison; retorna `false` sem throw para hash inválido

**apps/api/src/modules/auth/jwt.service.ts:**
- `onModuleInit()`: valida `AUTH_JWT_SECRET` (min 32 chars); em prod lança se ausente; em dev usa fallback com warn
- `signAccess(payload)`: JWT HS256 com claims `{sub, contabilidadeId, role}`, TTL 15min
- `verifyAccess(token)`: retorna `AccessTokenPayload | null` (nunca lança)
- `signRefresh()`: 32 bytes `crypto.randomBytes` → 64 hex chars
- `hashRefreshToken(token)`: sha256 hex 64 chars para armazenamento em DB

**apps/api/src/modules/auth/sessions.service.ts:**
- `create({userId, refreshToken, ip, userAgent})`: persiste com `refreshTokenHash = sha256(token)` + `expiresAt = now + 7d`
- `findActiveByRefreshHash(hash)`: filtra `revokedAt=null AND expiresAt>now`
- `revoke(sessionId)`: seta `revokedAt = now()`
- `rotateRefresh(oldSessionId, opts)`: revoga ANTES de criar nova (single-use enforcement)

**Config updates:**
- `env.schema.ts`: `AUTH_JWT_SECRET` (min 32 chars, optional — fail-fast em prod via JwtService) + `ALLOW_HEADER_AUTH`
- `redact-paths.ts`: adicionado `req.body.password` + `req.body.confirmPassword`
- `package.json`: `@node-rs/argon2@^2.0.2`, `jose@^6.2.2`, `@fastify/cookie@^11.0.2`

**Specs (20 testes):**
- `auth-password.spec.ts` (5): hash argon2id, verify true/false/hash-inválido, params corretos
- `auth-jwt.spec.ts` (9): round-trip, expirado, secret-errado, malformado, signRefresh, hashRefreshToken
- `sessions.spec.ts` (6): create com hash, create expiresAt, findActive null, revoke, rotateRefresh

### Task 2: AuthService + AuthController + AuthGuard + AuthModule (commit `b6f7d96`)

**apps/api/src/modules/auth/auth.guard.ts:**
- `PUBLIC_KEY` + `@Public()` decorator (preservado; importado por health.controller)
- `AuthContext`: `{userId, contabilidadeId, role}` — sem `orgRole` (não existe no modelo in-house)
- `ACCESS_COOKIE = 'nf_access'`, `REFRESH_COOKIE = 'nf_refresh'` (constantes exportadas)
- `canActivate()`: lê `req.cookies.nf_access` → `jwt.verifyAccess()` → popula `req.auth`
- Header auth fallback: `ALLOW_HEADER_AUTH=true AND NODE_ENV≠prod/staging` → aceita `x-user-id`

**apps/api/src/modules/auth/auth.service.ts:**
- `signup(dto, ip, ua)`: verifica duplicata (409 se existir), hash argon2id, cria user, membership platform_admin se count=1, cria session
- `signin(dto, ip, ua)`: mensagem genérica em AMBOS branches email-não-existe e senha-errada (T-02.1-02-01)
- `signout(refreshToken)`: idempotente — session não encontrada → OK sem erro
- `refresh(refreshToken)`: rotate single-use, emite novo access token
- `me(userId)`: strip `passwordHash` antes de retornar

**apps/api/src/modules/auth/auth.controller.ts:**
- `POST /api/auth/signup` @Public — cria user + cookies nf_access (15min) + nf_refresh (7d)
- `POST /api/auth/signin` @Public — valida credentials + seta cookies
- `POST /api/auth/signout` — revoga session + clearCookie
- `POST /api/auth/refresh` @Public — rotaciona refresh + novos cookies
- `GET /api/auth/me` — retorna user sem passwordHash
- Cookies: `HttpOnly, SameSite=Lax, Secure(prod), Path=/` para nf_access; `Path=/api/auth/refresh` para nf_refresh

**apps/api/src/modules/auth/auth.module.ts** (substituiu Clerk):
- Providers: `PasswordService, JwtService, SessionsService, AuthService, AuthGuard`
- Exports: `AuthGuard, JwtService, PasswordService`

**apps/api/src/app.module.ts:**
- Removeu `import { ClerkGuard }` → adicionou `import { AuthGuard } from './modules/auth/auth.guard'`
- `APP_GUARD: AuthGuard` (substituiu ClerkGuard)
- Comentário atualizado: "Auth In-House (Phase 02.1)"

**apps/api/src/main.ts:**
- Adicionou `import cookie from '@fastify/cookie'` + `await app.register(cookie)`

**Deletados:**
- `apps/api/src/modules/auth/clerk.guard.ts` — substituído por auth.guard.ts
- `apps/api/src/modules/auth/clerk.strategy.ts` — Clerk não mais usado
- `apps/api/tests/clerk-auth-smoke.spec.ts` — cobria ClerkGuard; substituído por auth-guard.spec.ts

**Specs (18 testes):**
- `auth-flow.spec.ts` (10): signup retorna tokens, JWT verificável, email duplicado, signin erros genéricos, refresh válido/inválido, signout idempotente
- `auth-guard.spec.ts` (8): @Public bypass, JWT válido popula req.auth, cookie ausente, token inválido, secret errado, header auth dev, header auth prod bloqueado, x-contabilidade-id preservado

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Import @nexo/shared/auth subpath rejeitado por moduleResolution:Node**
- **Found during:** Task 2 — `pnpm --filter @nexo/api typecheck` retornou TS2307 em `auth.controller.ts` e `auth.service.ts`
- **Issue:** `tsconfig.json` do API usa `moduleResolution: "Node"` que não suporta `package.json#exports` subpaths (necessário `node16`, `nodenext` ou `bundler`)
- **Fix:** Substituídas as importações de `@nexo/shared/auth` por `@nexo/shared` (root export que já re-exporta tudo de `./auth/index`)
- **Files modified:** `apps/api/src/modules/auth/auth.controller.ts`, `apps/api/src/modules/auth/auth.service.ts`
- **Commit:** `b6f7d96`

**2. [Rule 2 - Missing] clerk-auth-smoke.spec.ts referenciava arquivos deletados**
- **Found during:** Task 2 — ao deletar `clerk.guard.ts` e `clerk.strategy.ts`, `clerk-auth-smoke.spec.ts` ficaria órfão e causaria falha na suite
- **Fix:** Deletado `clerk-auth-smoke.spec.ts` — funcionalidade coberta por `auth-guard.spec.ts` (8 testes mais abrangentes)
- **Files deleted:** `apps/api/tests/clerk-auth-smoke.spec.ts`
- **Commit:** `b6f7d96`

**3. [Rule 1 - Bug] orgRole removido do AuthContext**
- **Found during:** Task 2 — `AuthContext` do `clerk.guard.ts` incluía `orgRole: string | null` mas `TenantContextMiddleware` e `RolesGuard` nunca usaram esse campo (apenas `userId`, `contabilidadeId`, `role`)
- **Fix:** `AuthContext` em `auth.guard.ts` sem `orgRole` — interface mais limpa e compatível com todos os consumidores
- **Files modified:** `apps/api/src/modules/auth/auth.guard.ts`
- **Commit:** `b6f7d96`
